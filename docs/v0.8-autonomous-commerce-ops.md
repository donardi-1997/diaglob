# Diaglob V0.8 — Autonomous Commerce Operations

## Objective

Turn the current agent, commerce, tracking, customer intelligence and visual
automation foundations into an explicit AI Workforce that can operate the
commerce lifecycle with permission-aware actions.

## Ten-point scope

| # | Workstream | V0.8 target |
|---|---|---|
| 1 | AI Workforce UI | Canonical roles surfaced in Agents with safe presets |
| 2 | Sales Agent | Catalog/Knowledge-aware sales role and sales templates |
| 3 | Support/Tracking Agent | Order + shipment grounded support role |
| 4 | Logistics Agent | Fulfillment/tracking monitoring role |
| 5 | Retention Agent | Customer-segment driven reactivation role |
| 6 | Analyst Agent | Internal data/decision role on top of authorized tools |
| 7 | One-click templates | Prefer durable visual flows; legacy templates remain compatibility-only |
| 8 | Instagram Messaging | Reuse Conversation/Message channel model; add Meta connector/webhook in dedicated integration slice |
| 9 | Warranties/Returns | Persisted PostSalesCase + immutable timeline + store-scoped API/UI |
| 10 | Logistics events | Canonical automation events for delivery exceptions and post-sales lifecycle |

## Architectural rules

1. One shared context model; do not build isolated chatbots per role.
2. Agent.role stores a canonical role code. Prompt instructions resolve server-side.
3. Every write capability stays behind ActionPolicy / explicit approval where applicable.
4. Post-sales cases are organization + store scoped and validate linked orders.
5. External channels map into the existing Conversation / Message domain.
6. Visual Flow Builder is the primary automation product; legacy automations are compatibility only.
7. Provider-specific logistics statuses must normalize before automation rules consume them.
8. No fake integrations: Instagram/voice/carriers are only shown connected after real provider verification.

## Delivery slices

### Slice A — Workforce + post-sales foundation
- workforce role catalog
- role-aware prompt instructions
- post-sales model/service/API/UI
- permissions
- post-sales automation events

### Slice B — Durable one-click flow templates
- order confirmation
- failed checkout recovery
- VIP follow-up
- customer reactivation
- delivery exception follow-up
- post-sales case acknowledgement
- review/cross-sell after delivery once canonical delivery trigger is wired

### Slice C — Instagram
- Meta OAuth/credential lifecycle
- signed webhook verification
- inbound normalization into Conversation(channel=instagram)
- outbound delivery
- unified inbox badge/filter
- AI auto-reply through the existing agent pipeline

### Slice D — Logistics event bus
Canonical events:
- shipment.created
- shipment.in_transit
- shipment.out_for_delivery
- shipment.delivered
- shipment.delayed
- shipment.failed
- shipment.delivery_exception
- shipment.returned

### Slice E — Voice confirmation
Add only after measuring COD confirmation need. Voice is a provider adapter behind
a confirmation policy; it must not call every order by default.
